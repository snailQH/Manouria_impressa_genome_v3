Reference-quality genome · PacBio HiFi + Hi-C + RNA-seq

From raw reads to a chromosome-scale, annotated, reproducible genome

The workflow we built for the Manouria impressa v3 reassembly, written as a protocol that transfers to any diploid vertebrate (and, with the noted changes, to other eukaryotes). Each step names the tool, the parameters that matter, what it hands to the next step, and the mistake we made there — so nobody makes it twice.

Five rules the workflow enforces

  • Count the data from the files, not the vendor report. Reads, bases, platform (from read headers), coverage against both the k-mer genome-size estimate and the final assembly. Every number in Table 2 of a Data Descriptor comes from step 0.
  • One script per step, versions pinned, job IDs logged. The protocol log (PROTOCOL_v3.md) is written as the work happens and becomes the Methods. Failed attempts stay in it with their cause.
  • Scaffolding decisions are measured, not eyeballed. Every join — the scaffolder's and ours — is scored by the same Hi-C statistic, calibrated on the scaffolder's own joins and on one join verified by eye.
  • Anomalies get an explanation before release. Zero-coverage runs are classified (artefact vs. heterozygous duplication vs. unmappable repeat) from unfiltered read depth and haplotype comparison, and reported.
  • The previous assembly is a comparison column, never an input. Independence from earlier builds is what lets the new release stand on its own statistics.

The steps, in order

Numbers in parentheses are what each step took on a 2.4-Gb genome with 30× HiFi and 33 M Hi-C pairs, on one 64-CPU node.

Data
0

Raw-data accounting (14 min)

Count every library from the files: reads, bases, mean and N50 read length, platform from the BAM/FASTQ headers, SMRT cells, Hi-C ligation-junction fraction (GATCGATC for MboI/DpnII). Record what does not exist (e.g. no short reads for polishing).

samtools view hifi.bam | awk '{L=length($10); ...}' # per-read length + rq tag + movie zcat hic_R1.fq.gz | head -400000 | awk 'NR%4==2' | grep -c GATCGATC
raw_stats table · platform/kit from @RG · coverage = bases / genome size
1

HiFi preparation and k-mer survey (5 h, mostly extraction)

Keep reads with CCS accuracy rq ≥ 0.99 (Q20); remove reads carrying the SMRTbell adapter (≤ 2 mismatches, the HiFiAdapterFilt criterion); count 21-mers with meryl; estimate size, heterozygosity, repeat fraction and error rate with GenomeScope2.

samtools view -e '[rq]>=0.99' -b hifi.bam | samtools fastq -T rq - | pigz > hifi.q20.fq.gz # NOT -0 /dev/null seqkit grep -s -m 2 -p ATCTCTCTCTTTTCCTCCTCCTCCGTTGTTGTTGTTGAGAGAGAT ... | seqkit seq -n -i > adapter_hits.ids meryl k=21 count output k21.meryl hifi.q20.filt.fq.gz; meryl histogram k21.meryl > k21.histo; genomescope2 -i k21.histo -p 2 -k 21
hifi.q20.filt.fastq.gz · k21.meryl (reused by Merqury) · genomescope2/summary.txt
Contigs
2

hifiasm in Hi-C-integrated mode (4 h 52 min, 119 GB RAM)

One run yields the primary assembly and two phased haplotypes. Defaults; the only choice is to pass the Hi-C reads. For a genome with < 0.5 % heterozygosity expect the haplotypes to be much less contiguous than the primary — that is normal.

hifiasm -o IT1 -t 60 --h1 hic_R1.fq.gz --h2 hic_R2.fq.gz hifi.q20.filt.fastq.gz for g in hic.p_ctg hic.hap1.p_ctg hic.hap2.p_ctg; do gfatools gfa2fa IT1.$g.gfa > IT1.$g.fa; done
IT1.hic.p_ctg.fa · IT1.hic.hap1.p_ctg.fa · IT1.hic.hap2.p_ctg.fa · hifiasm log (coverage peaks)
Scaffolds
3

Map Hi-C once per assembly, to disk (25 min each)

chromap with the Hi-C preset, MAPQ ≥ 1, PCR duplicates removed. Write SAM to a file — chromap aborts when streaming SAM to stdout. From the one SAM derive the two inputs scaffolders want: a name-sorted BAM (YaHS) and a -F 3340 filtered BAM (HapHiC).

chromap -i -r ctg.fa -o ctg.index chromap --preset hic -r ctg.fa -x ctg.index -q 1 --remove-pcr-duplicates -t 48 --SAM -1 R1 -2 R2 -o hic.sam samtools sort -n -o hic.namesorted.bam ...; samtools view -b -F 3340 -o hic.filtered.bam ...
hic.namesorted.bam · hic.filtered.bam · chromap.log · 03f_hic_stats → pairs sequenced, mapped, unique, valid (dedup + MAPQ ≥ 1 + proper), cis/trans — the "valid pairs" numbers reviewers ask for
4

Scaffold with two tools and compare (YaHS 52 min; HapHiC 10 min)

YaHS on the primary; HapHiC on hap1, hap2 and the primary with the expected chromosome number. Strip the /1 /2 mate suffixes before YaHS or it reads zero pairs. Compare N50, join count and — decisively — the size distribution: a correct chromosome-scale assembly steps cleanly at the karyotype number.

samtools view -h hic.namesorted.bam | awk 'BEGIN{OFS="\t"} /^@/{print;next} {sub(/\/[12]$/,"",$1);print}' | samtools view -b -o nosuffix.bam - yahs -o yahs -e GATC ctg.fa nosuffix.bam; juicer pre -a -o out_JBAT yahs.bin yahs_scaffolds_final.agp ctg.fa.fai haphic pipeline ctg.fa hic.filtered.bam 26 --RE GATC --threads 48
yahs_scaffolds_final.fa/.agp · out_JBAT.hic/.assembly (Juicebox) · haphic 04.build/scaffolds.fa
5

Contact maps and synteny (32 min + 41 min)

PretextMap of each scaffold set (whole-genome and per-scaffold snapshots) and a minimap2 asm20 alignment to the nearest chromosome-level reference. Synteny is a guide to where to look; the Hi-C decides. Expect it to mis-assign some small scaffolds.

samtools view -h hic.bam | PretextMap -o map.pretext --sortby length --mapq 1; PretextSnapshot -m map.pretext --sequences "=all" minimap2 -x asm20 --secondary=no ref_chr.fa scaffolds.fa > aln.paf # → scaffold_to_ref.tsv + dot plot
FullMap.png · per-scaffold PNGs · dotplot.png · scaffold_to_ref.tsv (best chromosome, % aligned, second hit)
Curation
6

Score every join (≈ 15 min, one BAM pass)

join_qc.py: for each contig boundary inside a scaffold, read pairs linking the 2 Mb before to the 2 Mb after, divided by (a) the expectation for contiguous sequence from the genome-wide distance-decay curve measured inside contigs and (b) the inter-scaffold background. Calibrate the thresholds on the scaffolder's own joins; verify one join by eye in Juicebox as a positive control.

python3 join_qc.py hic_scaffold.bam scaffolds.agp scaffolds.fa.fai join_qc.tsv candidates.tsv
join_qc.tsv: ratio, bg, verdict per join · candidate joins scored at both orientations
7

Find where unplaced scaffolds belong (≈ 10 min)

curation_contacts.py: for every small scaffold, pairs with each chromosome-scale scaffold (enrichment vs. size-expected), binned along the partner to see whether contact is end-concentrated (adjacent) or spread (haplotig / repeat compartment). For a suspected seam inside a scaffold: contact across the seam vs. within, by distance.

curation_contacts.txt · worklist with verdicts
8

Apply, remap, re-score (edits seconds; verification ~45 min)

apply_curation.py breaks joins below the break threshold, joins candidates above the join threshold with orientation from contact asymmetry, writes AGP + FASTA + edit log. Then remap Hi-C and run join_qc.py again: new joins must fall inside the accepted distribution, broken ones must be gone. Open the final map once in Juicebox/PretextView.

python3 apply_curation.py yahs.agp ctg.fa hic_scaffold.bam v3_curated sbatch 03e_verify_curation.sbatch v3_curated v3_curated.fa v3_curated.agp
v3_curated.fa/.agp/.names.tsv/.edits.log · join_qc_v3_curated.tsv · curated map
QC
9

Completeness and accuracy (QC 6 h; Merqury 1 h 45)

compleasm on the current odb12 lineages and BUSCO on the legacy odb10 lineage the previous paper used (so the comparison is like-for-like); Merqury QV and k-mer completeness against the step-1 meryl database, for the primary alone and for hap1 + hap2 together (phasing / diploid completeness). Run Merqury only after the meryl DB is complete.

compleasm run -a asm.fa -l vertebrata_odb12 -t 48; busco -i asm.fa -l vertebrata_odb10 -m genome --offline merqury.sh reads.k21.meryl asm1.fa [asm2.fa] out # symlinks, absolute $MERQURY
compleasm summary · BUSCO short_summary · merqury.qv · merqury.completeness.stats
10

HiFi coverage track and anomaly triage (1 h 11)

minimap2 map-hifi of all HiFi reads to the scaffolds; mean depth per 10-kb window at MAPQ ≥ 1; list zero-coverage runs (< 5 % of median) and high runs (> 2.5×). For each run on a chromosome: count reads at all MAPQ, and align the region to hap1/hap2. Reads present but MAPQ 0 + a half-length hap2 copy = heterozygous tandem duplication (keep, report); no reads at any MAPQ = unsupported sequence (trim).

hifi.bam · depth10k.bed · zero_coverage_runs.bed · explanation per run
11

Contamination and organelle (adaptor 10 min; GX ≈ 2 h per assembly, 450 GB RAM; MitoHiFi ≈ 2 h)

NCBI FCS-adaptor and FCS-GX on every assembly you will deposit (primary and both haplotypes). The GX database is ~470 GB: download it on a node with internet, verify every file size against the NCBI listing, write a .complete flag, and make the screening scripts refuse to run without it — a half-downloaded index does not error, it just misses things. Mitogenome from the HiFi reads with MitoHiFi; compute nodes usually cannot reach NCBI, so fetch the reference (efetch FASTA + GenBank of the closest published mitogenome) on the head node and pass it with -f/-g. Then align the mitogenome to each nuclear assembly: sequences ≥ 80 % covered are mitochondrial and are removed before deposit; partial hits inside chromosomes are NUMTs and stay.

av_screen_x -O adaptor --euk asm.fa fcs.py screen genome --fasta asm.fa --out-dir gx --gx-db gxdb --tax-id 74924 # only when gxdb/.complete exists mitohifi.py -r hifi.fq.gz -f NC_011815.1.fasta -g NC_011815.1.gb -t 16 -o 2 minimap2 -x asm10 asm.fa mito.fa | awk '$12>=30' → per-sequence % covered
fcs_adaptor_report.txt · *.fcs_gx_report.txt · final_mitogenome.fasta/.gb + circular map → 06_release/Mimp_v3_mito.* · *.mito_hits.tsv (sequences to drop)
Annotation
12

Repeat library and soft-masking (RepeatModeler ≈ 3 days)

RepeatModeler2 -LTRStruct on the scaffolds (start it as soon as scaffolds exist — it does not depend on curation; the library is re-applied to the curated sequence). RepeatMasker in two passes: the species library, then Dfam Tetrapoda on the masked output; union of both GFFs.

singularity exec tetools.sif RepeatModeler -database genome -threads 60 -LTRStruct RepeatMasker -pa 15 -xsmall -gff -lib genome-families.fa genome.fa; RepeatMasker -pa 15 -xsmall -gff -species tetrapoda genome.fa.masked
genome-families.fa · genome.softmasked.fa · repeats.gff · masked fraction + class table · repeat landscape (12_repeat_landscape.py: divergence histogram per class from the .out files)
13

Gene prediction with BRAKER3

Align RNA-seq yourself with HISAT2 (inside the container, so versions are logged) and pass BAMs; proteins = OrthoDB v12 partition for the clade. BRAKER3 runs GeneMark-ETP + AUGUSTUS and outputs isoform-aware models. Test immediately: does the annotation recover a locus you know the old annotation missed?

hisat2-build genome.softmasked.fa idx; hisat2 --dta -x idx -1 R1 -2 R2 | samtools sort -o IT3.bam braker.pl --genome=genome.softmasked.fa --prot_seq=orthodb_vertebrata.fa --bam=IT3.bam,IT4.bam --threads=48 --gff3 --busco_lineage=vertebrata_odb10
braker.gff3 · braker.aa · braker.codingseq · BUSCO-protein score
14

Annotation QC, functional and non-coding annotation (≈ 8 h)

Gene-set statistics from the GFF3 (genes, transcripts, exons/transcript, mean CDS/exon/intron length, single-exon fraction) — reviewers ask for these numbers, and BRAKER does not print them. BUSCO in protein mode on the longest isoform per gene. eggNOG-mapper (DIAMOND, tax scope Vertebrata, non-electronic GO) gives GO/KEGG/COG/Pfam and a preferred name in one pass; report the annotated fraction per database. tRNAscan-SE 2 (-E) and barrnap (--kingdom euk) for tRNA/rRNA. InterProScan and Rfam are optional extras (large downloads).

busco -i proteins.longest.faa -l vertebrata_odb10 -m proteins emapper.py -i proteins.longest.faa -m diamond --tax_scope 7742 --go_evidence non-electronic tRNAscan-SE -E genome.fa; barrnap --kingdom euk genome.fa
gene_set_stats.tsv · BUSCO-protein summary · eggnog.emapper.annotations · trna.out/.bed · rrna.gff
Release
15

Name, orient, package

Chromosomes named by size (chr1…chrN) from this step on; orientation matched to the reference where syntenic; unplaced scaffolds keep scaffold names. Haplotypes are not chromosome-named (block-phased): rename by length (h1_scaffold_N), drop < 1 kb, and align each to the primary for a correspondence table. Telomere arrays in the terminal 50 kb of every chromosome; a whole-genome alignment of the previous release for a liftover table; software_versions.sh exports every tool version from the environments and containers; md5 of every release file. Final statistics computed by asm_stats.py from the released FASTA + AGP — the only source for Table 2.

name_chromosomes.py curated.fa curated.agp curated_vs_ref.paf 26 Mimp_v3 08_haplotype_release.sbatch; 09_telomere.py Mimp_v3.fa; 10_compare_v2.4.sbatch; software_versions.sh
Mimp_v3.fa/.agp/.names.tsv · Mimp_v3_hap1/2.fa + hapN_to_primary.tsv · telomeres.tsv · v2.4_to_v3_correspondence.tsv · software_versions.tsv · release_md5.txt
15b

Numbers that make the paper comparable (≈ 2 h)

Three cheap analyses reviewers of genome notes expect. Haplotype divergence: align hap1 to hap2 and each to the primary (minimap2 asm5 --cs, paftools.js call) and report SNV, small-indel and SV (≥ 50 bp) densities — the number behind "two haplotypes", cross-checked against the k-mer heterozygosity. Repeat landscape from the RepeatMasker output (no re-run needed). EBP quality notation from Table 2: log₁₀ contig N50 · log₁₀ scaffold N50 · QV (here 7.8.Q67) and the fraction of the assembly in chromosomes. Optional for a Data Note, common in GigaScience genome notes: an orthology/species-tree analysis (OrthoFinder on ~8 proteomes) once the gene set exists.

minimap2 -cx asm5 --cs hap2.fa hap1.fa | sort -k6,6 -k8,8n | paftools.js call -l 10000 -L 50000 - 12_repeat_landscape.py genome_size landscape.png landscape.tsv rm_custom/*.out rm_dfam/*.out
hap_divergence_summary.tsv · repeat_landscape.png/.tsv · EBP string in Table 2
16

Audit before you write

Before drafting, check every reviewer point, every Data-Descriptor section and every deposition object against what actually exists on disk, and look for jobs that "completed" in seconds. Our audit found seven real gaps and two silent failures (MitoHiFi with no NCBI access; a contamination screen armed on a partial database) — all cheaper to fix a week before submission than in a second round of review.

Quantitative curation — how a join is judged

Two statistics per boundary, both from the scaffold-level Hi-C BAM (MAPQ ≥ 1, read-1 records, 100-kb bins, 2-Mb windows):

statisticdefinitioncorrect joinmisjoin
ratioobserved pairs across the boundary ÷ expected for contiguous sequence (distance-decay curve measured inside contigs)0.3–0.7 (contig ends are repeat-rich, so always below 1)≈ 0–0.1
bgobserved ÷ inter-scaffold background for the same windows≥ 11 (5th percentile of the scaffolder's joins; median ≈ 46)≤ 5
decisionrule
breakexisting join with bg < 5
joincandidate adjacency with bg ≥ 11 at the junction windows and end-concentrated contact in the partner-binned profile; orientation = the half of the small scaffold with more contact to the partner's terminal 1 Mb faces it
not joinedenrichment present but junction bg between 5 and 11 — the pieces are near but sequence is probably missing between them; leave unplaced and record the association
seam inside a scaffoldacross-seam contact well above inter-chromosomal background and approaching within-arm contact at ≥ 10 Mb = one chromosome (a centromere depresses short-range contact); at background = misjoin
Calibrate before deciding. Thresholds come from the distribution of the scaffolder's own joins on this dataset, and one join must be checked by eye in Juicebox as the positive control. In our run the eye-verified join scored bg 45, exactly the median.

Adapting to another species

  • Karyotype: set the HapHiC group count and the expected number of chromosome-scale scaffolds from the literature 2n. If unknown, run HapHiC with a range and let YaHS's size distribution suggest it.
  • Restriction enzyme: confirm from the reads (junction motif) — MboI/DpnII = GATC (-e GATC); Arima = GATC,GANTC; HindIII = AAGCTT.
  • Heterozygosity: above ~1 % expect better haplotype contiguity and possible retained haplotigs in the primary (watch compleasm duplication; consider purge_dups).
  • Ploidy / sex chromosomes: this workflow assumes a diploid without sex chromosomes (TSD reptile). For XY/ZW species, scaffold the haplotypes and check whether a chromosome-scale scaffold has half coverage.
  • Reference for synteny: nearest chromosome-level assembly; rename its chromosomes from the FASTA headers as in 03d_synteny.sbatch.
  • Lineages and proteins: compleasm/BUSCO lineage and the OrthoDB partition for the clade; --species name in BRAKER.
  • Plants, fungi, large repeat fractions: raise RepeatModeler time, consider hifiasm -l0/-l1 for highly homozygous lines, and FCS-GX becomes mandatory for field-collected samples.
  • Memory: hifiasm peak ≈ 50 GB per Gb of genome at 30×; YaHS and chromap < 100 GB; RepeatModeler 60 threads comfortably in 200 GB.
